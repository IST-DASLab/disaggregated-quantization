Training, export and serving audit — 2026-10-16

User decision: norms, embeddings and LM head are SHARED and FROZEN from the
external decoder. Do not replace an old checkpoint's specialized norms silently.

New training contract
---------------------
Only NVFP4 text projection masters train. Token embeddings, LM head, all text
norms, GDN in_proj_a/b, convolution, A_log and dt_bias are frozen decoder values.
Shared storage/activations are BF16; trainable masters/gradients remain FP32.
The normal HF cache is used, without offloading.

For each projection, W ~= gW * FP8_block_scale * FP4_code. Blocks contain 16
values along K. The activation uses the same two-level scheme with gA.
Compressed-tensors stores 1/gW and 1/gA; ODP stores gW and gA in GGUF metadata.
The runtime applies gW*gA after the scaled FP4 dot product.

Attention Q/K/V, MLP gate/up and (for NEW runs) GDN QKV/Z each share tensor-global
scales within their group. Their WEIGHT MATRICES ARE DISTINCT. Sharing scales
allows vLLM's concatenated GEMM; llama.cpp can still run separate GEMMs with the
same values. No existing trained projection is regrouped/requantized at export.

Global activation scales are calibrated on all ranks before optimization, MAX
reduced, then frozen throughout training and export. Per-block activation scales
remain dynamic. Before every DCP save, replicated observers are synchronized.
Static resume restores the fixed scales; changing observer mode requires an
explicit recalibration request. Quantization-contract fields in student-config/
are restored rather than inferred from the base teacher when exporting/resuming.

Native activation rounding uses nearest-even. Historical weight packing remains
unchanged. The new activation rounder matched stock vLLM's GPU quantizer exactly
on 393216 sampled BF16 values and the explicit midpoint regression. This is an
activation-quantizer check, not a bit-exact whole-model inference claim.

The new phase mask matches hybrid NIXL: the final prompt token is evaluated on
the decoder, producing the first output logits. Earlier prompt positions use
prefill weights; assistant tokens use frozen decoder weights. The actual cached
training corpus contains 32059 documents, all with one assistant span, so no
historical-assistant-as-prompt ambiguity was found in this run.

Automatic export
----------------
After the final resumable checkpoint, rank zero releases the training models,
exports the real compressed-tensors NVFP4 model, attaches frozen BF16 vision and
processor assets for the real model, exports ODP GGUF blocks, then launches STOCK
vLLM for text/image HTTP checks. No custom serving entrypoint is used by this
check. A failed check fails the command while preserving the final checkpoint.
Tokenizer files are explicitly saved with FSDP checkpoints: Accelerate's save
path bypassed the previous _save() tokenizer hook.

Packed export validation checks real UINT8 FP4 codes, FP8 block-scale shapes,
positive global scales, fusion-group agreement, inference cache config and
standalone tokenizer assets. Outputs are staged before publication. Only an
existing validated artifact belonging to the same run can be replaced.

training and rank-zero validation calibration before exports, without resetting

Its single-rank model export avoids DCP's mixed-writer observer-buffer problem.

GGUF export of the legacy run
----------------------------
prefill-gguf/ contains 64 real ODP GGUF layer files and export_manifest.json.
All 400 NVFP4 projections and 48 BF16 gate projections were read back and checked
byte-for-byte, including every FP4 code, FP8 block scale and global-scale header.
No tensor or global scale was requantized or reconciled. The original individual
scales can be retained because this ODP format stores projections separately.
The manifest records that specialized source norms are omitted by the shared-
norm runtime. These are usable ODP-format projection blocks, not evidence that
the old complete trained model is preserved when using shared decoder norms.

New-contract verification
-------------------------
Two-GPU tiny FSDP training, saving, static-scale resume, packed export and replacing
the run's prior export pass. The fresh automatic export includes its tokenizer
and chat template. Stock vLLM HTTP generation passes with native NVFP4 kernels,
no scale-collapse warnings and no serving patches. See:
transformers/outputs/audit-automatic-serving-smoke/serving-check/serving-check.json
The final pipeline smoke adds automatic GGUF export as well.

Targeted regressions cover synchronized two-rank DCP observer saves/loads,
unchanged packed weights during explicit legacy observer reconciliation, static
observer freezing, shared decoder norms, native midpoint rounding, phase masks,
cached KV/recurrent-state handoff vs full mixed forward, export/tokenizer assets,
and GGUF byte-level round trips. Full-model numerical parity is not established
by these tests or by successful HTTP generation.

Remaining cross-runtime difference
----------------------------------
Exact linked llama.cpp commit:
https://github.com/IST-DASLab/disaggregated-llama.cpp/commit/967b479a5ab04c967a0591d02e130b4b35dbfe3d

It activates ODP for ubatch.n_tokens > 1 and otherwise uses the decoder. A normal
multi-token prompt therefore includes its final token on the prefiller. Stock
vLLM hybrid NIXL explicitly transfers through N-1 and evaluates that final token
on the decoder. Norm/global-scale consistency does not eliminate this difference.
The linked runtime needs its final-token scheduling changed before one may claim
the NEW model has the same handoff in both runtimes. Its behavior for a one-token
tail of a chunk and batches containing multiple decoding sequences also needs
explicit phase scheduling rather than classifying phase solely by batch size.

The eval runner now rejects a legacy prompt-end prefiller before GPU startup and
uses FP32 recurrent-state storage to avoid NIXL's default BF16 state truncation.
Only the baseline's small smoke completed before evaluation was paused. There
are no completed MMLU-Pro/MMMU-Pro combo scores to report.

Native llama.cpp IQ1_S matmuls and dequantized-BF16 decoder matmuls may also differ
numerically, as may native FP4 accumulation and fake-quant BF16 GEMMs. Quantization
and layout agreement do not imply bit-exact outputs across these kernels. Full
runtime cache/state/logit parity remains a separate required validation.
