Qwen3.8 prefiller training: handoff for B200 x 8
Date: 2026-10-14

USER INTENT AND CURRENT STATE

Implement the qad/training/qad.py nvfp4frozendec recipe with Hugging Face
Trainer, existing UV environment, bare metal, no Slurm or vLLM runtime.
The user requested stopping after validation/MFU, then cleanup, commit and this
handoff for a B200 x 8 machine. Do not start a long training run automatically.
The earlier prohibition on committing was explicitly superseded by that request.
All local training processes were stopped; all 10 L40S GPUs were idle afterward.

REQUIRED SEMANTICS: PRESERVE THESE

Teacher: Qwen/Qwen3.8-27B-FP8, real HF FP8 storage and kernels, frozen/eval.
Student: FP32 trainable masters initialized by HF FineGrainedFP8Config with
dequantize=True. BF16 autocast for GEMMs must not replace FP32 stored masters.
Decoder: ISTA-DASLab/GSQ-RCO-small,
Qwen3.8-27B-GSQ-RCO-IQ1_S.gguf. Stream dequantization directly into frozen
student parameters; do not create an intermediate dense checkpoint.

The trainable/shared partition matches the reference quantizer. Specialized
prefill linear masters and norm scales train. Separate decode matrices and
norm scales are frozen. Embeddings/head, in_proj_a/b, A_log, dt_bias, convolution
and other shared parameters are single frozen objects reused by both phases.
Shared frozen values MUST come from the decoder, the inference source of truth.
This deliberately differs from the original script's base initialization for
those shared parameters. Norms are specialized in the reference, not shared.
Do not put the student decode branch under no_grad: gradients through its inputs
are required. Keep the routing mask active through checkpoint recomputation.

CURRENT PARALLELISM

FSDP2 across every local GPU. Different complete-sequence batches per rank;
no TP or CP implementation. Each student/teacher decoder block and embedding
is an FSDP unit; remaining heads/parameters belong to the root. Blocks reshard
after forward. Teacher retains FP8, frozen decode matrices BF16, other student
parameters FP32. MixedPrecisionPolicy(param_dtype=None, reduce_dtype=float32)
is intentional: casting FP8 storage without scales would silently corrupt it.
Activation checkpointing is enabled. CPU offload is currently the default.
Global batch = ranks * --batch-size * --gradient-accumulation-steps.
Default 10-rank global batch is 40; 8 ranks with defaults gives 32.

Controls:
  NPROC_PER_NODE, CUDA_VISIBLE_DEVICES, HOST_MEMORY_LIMIT_GIB (default 768)
  --batch-size, --gradient-accumulation-steps, --max-seq-len
  --logit-chunk-size (default 16; real-model runs used 128)
  --no-cpu-offload (all shards, gradients and Adam state stay on GPU)
  --teacher-resident (teacher block/embedding shards stay on GPU)
  --student-resident-layers N (first N student blocks, gradients and Adam stay GPU)
  --activation-offload (saved checkpoint inputs go to CPU)
  --no-save-checkpoints (disposable benchmark; still evaluates/saves log history)

B200 x 8 STARTING PLAN

1. Inspect GPU memory, topology, driver and host RAM first. Reuse the target
   machine's UV .venv; install requirements through UV. Kernel wheels/toolchain
   support for Blackwell needs actual validation; this was only run on L40S.
   Inspect whether causal-conv1d can be installed for this stack. Its current
   fallback is correct but slower; FLA DeltaNet kernels are installed.

2. Start with all-GPU FSDP2 (--no-cpu-offload), no activation offload, eight ranks,
   batch/rank 1, sequence 8192, logit chunks 128. FP32 master + gradients + Adam
   plus frozen model storage are roughly 450 GiB total before active gathers,
   activations and scratch; verify actual peaks on the target. The L40S offload
   default is a fit baseline, not a recommendation for the B200 machine.

3. Run the tiny test, then a three-step real-model validation before a long run:

   UV_CACHE_DIR="$PWD/transformers/.cache/uv" uv pip install \
     --python .venv/bin/python -r transformers/requirements.txt

   NPROC_PER_NODE=2 bash transformers/run.sh --smoke-test --no-cpu-offload \
     --max-steps 2 --warmup-steps 0 --gradient-accumulation-steps 1 \
     --save-steps 2 --eval-steps 2 \
     --output-dir transformers/outputs/b200-smoke

   NPROC_PER_NODE=8 bash transformers/run.sh --no-cpu-offload \
     --max-steps 3 --warmup-steps 0 --gradient-accumulation-steps 1 \
     --train-tokens 100000 --val-tokens 10000 --max-seq-len 8192 \
     --logit-chunk-size 128 --no-save-checkpoints \
     --output-dir transformers/outputs/b200-validation

   These commands retain L40S MFU denominators! Add --bf16-peak-tflops and
   --fp8-peak-tflops using verified DENSE per-GPU B200 peaks before interpreting
   the utilization metrics. Do not use sparsity-enhanced marketing peaks.
   Adjust HOST_MEMORY_LIMIT_GIB to the actual host RAM/reserve policy.

4. To benchmark resume, copy checkpoint-4 to fast local storage if available,
   add --resume-from-checkpoint PATH and set --max-steps 7 (absolute global step,
   not three extra steps). DCP can reshard from 10 to 8 ranks in principle;
   this specific world-size change has NOT been tested here. Validate optimizer
   restoration and RNG/data-order implications. A fresh initialization is also
   available if cross-world-size resume fails. Do not claim exact sample-order
   continuation when world size/batch/dataset settings change.

5. Profile after warmup. Priorities: eliminate CPU transfers, inspect FSDP
   gather overlap/wrapping and root-head residency, optimize branch computation
   (currently both dense branches execute before token selection), consider
   padding/packing, install optimized causal convolution. More GPU memory could
   permit less recomputation. TP/CP require explicit quantizer and DeltaNet
   support and correctness checks; neither is exposed as a supported CLI mode.

6. Only after validation and user authorization, use full reference corpus:
   200M train tokens / 200K val tokens, 980 steps, LR 3e-6, warmup 100,
   accumulation 4 on 8 ranks gives global batch 32. Save/eval default every 50.

KNOWN PITFALLS / NEXT REVIEW

- Do not call from_pretrained independently on every rank for FP8/dequantized
  weights. HF's rank-zero optimization excludes this quantized path. An early
  attempt exceeded 1 TB host memory, stalled the host and lost a worker.
  Explicit metadata-only construction and the RSS guard are necessary.
- Resume builds metadata on ALL ranks and reads checkpoint shards directly;
  it does not reconvert/reload teacher or GGUF. CPU tensor allocations must have
  distinct data pointers for Accelerate optimizer remapping (all-meta pointers
  would collide). Persistent/nonpersistent quantizer buffers need care.
- Accelerate 1.15 private APIs are used in the buffer/residency workarounds.
  Revalidate after dependency changes; installed packages were never patched.
- Student norms/shared parameters stay FP32; only decode projection matrices
  are BF16. Stored FP8 teacher parameters/scales must preserve their schema.
- Native packed HF GGUF acceleration inspected here was Metal-oriented; no
  validated CUDA IQ1_S forward+input-backward training route was found. There
  is no measured IQ1_S CUDA speed claim. Current decoder is dequantized.
- The initial real MFU run had a callback bug suppressing per-step loss logs;
  metrics and final eval are valid. It also mislabeled the first resumed step
  as warm. Discard that first step (264.9 sec). Both callback issues are fixed
  and verified in the selective tiny logs.
- Full 27B prefiller export has not been executed, only tiny export.
- Final-evaluation state saving was moved after evaluate during cleanup;
  selective benchmark had already imported the previous order when stopped.
